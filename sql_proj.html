01

Overview

The warehouse follows a classic star schema: one central fact table, FactSales, holding every transaction line, surrounded by four dimension tables — customer, product, store, and a calendar reference table — joined by foreign keys. It's the same pattern used in real BI stacks to keep reporting queries fast and joins predictable.

On top of the schema sit 21 tasks spanning the full SQL toolkit an analyst needs day to day: updates and conditional deletes, string and date functions, revenue rollups through joins, correlated and non-correlated subqueries, and transaction control — commits, rollbacks, and savepoints — including a stored procedure with error handling.

Query gallery

Six categories of work, pulled straight from the project file. Each panel shows one representative query.

fact_sales.sql
-- FactSales: central transactional fact table
CREATE TABLE FactSales (
    SalesID       INT         auto_increment    PRIMARY KEY,
    DateKey       INT             NOT NULL,
    CustomerID    INT             NOT NULL,
    ProductID     INT             NOT NULL,
    StoreID       INT             NOT NULL,
    QuantitySold  INT             NOT NULL,
    UnitPrice     DECIMAL(10,2)   NOT NULL,
    TotalAmount   DECIMAL(10,2)   NOT NULL,
    PaymentMethod VARCHAR(30),
    CONSTRAINT FK_Date     FOREIGN KEY (DateKey)    REFERENCES DimDate(DateKey),
    CONSTRAINT FK_Customer FOREIGN KEY (CustomerID) REFERENCES DimCustomer(CustomerID),
    CONSTRAINT FK_Product  FOREIGN KEY (ProductID)  REFERENCES DimProduct(ProductID),
    CONSTRAINT FK_Store    FOREIGN KEY (StoreID)    REFERENCES DimStore(StoreID)
);

The fact table sits at the center of the star, referencing all four dimensions through foreign keys.

q3_delete_inactive_customer.sql
-- Q3: Delete an inactive customer record
DELETE FROM DimCustomer
WHERE CustomerID = 4023
AND NOT EXISTS (
    SELECT 1
    FROM FactSales s
    WHERE s.CustomerID = DimCustomer.CustomerID
);

Only removes the customer if they have zero linked sales — a safety check against orphaning fact rows.

q5_sales_date_functions.sql
-- Q5: Sales date functions
SELECT
    YEAR(d.FullDate)      AS SaleYear,
    MONTH(d.FullDate)     AS MonthNumber,
    MONTHNAME(d.FullDate) AS MonthName,
    DATEDIFF(CURDATE(), d.FullDate) AS DaysSinceSale
FROM FactSales s
JOIN DimDate d
    ON s.DateKey = d.DateKey;

Also covers string work — UPPER(), LEFT(), RIGHT(), LENGTH() — on customer names in Q4.

q7_monthly_sales.sql
-- Q7: Monthly sales via join
SELECT
    d.YearNumber  AS SalesYear,
    d.MonthNumber AS SalesMonth,
    d.MonthName   AS MonthName,
    SUM(s.TotalAmount) AS TotalSales
FROM FactSales s
JOIN DimDate d
    ON s.DateKey = d.DateKey
GROUP BY
    d.YearNumber, d.MonthNumber, d.MonthName
ORDER BY
    d.YearNumber, d.MonthNumber;

The same pattern powers per-store and per-product revenue rankings (Q6, Q9, Q12).

q14_top_product_subquery.sql
-- Q14: Product with the highest total revenue, via subquery
SELECT
    p.ProductName AS ProductName,
    SUM(s.TotalAmount) AS TotalRevenue
FROM FactSales s
JOIN DimProduct p
    ON s.ProductID = p.ProductID
WHERE s.ProductID = (
    SELECT ProductID
    FROM FactSales
    GROUP BY ProductID
    ORDER BY SUM(TotalAmount) DESC
    LIMIT 1
)
GROUP BY p.ProductName;

Q15 pairs this with a correlated subquery, counting each store's transactions inline against DimStore.

q19_savepoint_rollback.sql
-- Q19: Partial rollback using a savepoint
START TRANSACTION;

DELETE FROM DimStore WHERE StoreName = 'Store A';

SAVEPOINT mySavepoint;

DELETE FROM DimStore WHERE StoreName = 'Store B';

-- undo only the Store B deletion
ROLLBACK TO SAVEPOINT mySavepoint;

COMMIT;

Q17 rolls back a full price update; Q18 wraps an insert pair in a stored procedure with an exit handler that rolls back on any SQL exception.

Challenges & fixes

Two problems came up during the build, both documented as part of the project write-up.

01
Problem

Primary key without auto-increment

FactSales' primary key wasn't originally defined with AUTO_INCREMENT, so unique transaction IDs weren't generated automatically.

Fix

Altered the table structure to add AUTO_INCREMENT on SalesID.

02
Problem

SQL Server syntax in a MySQL project

The task hints were written in SQL Server syntax, which isn't compatible with MySQL — several keywords and functions needed translating.

Fix

Swapped each SQL Server construct for its MySQL equivalent, shown below.
